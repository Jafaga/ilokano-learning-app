# Content Guide for Ilokano Contributors

## Goal

Contributors help build accurate, respectful, and useful Ilokano lessons. The developer should not have to guess whether a word or sentence is correct. The contributor workflow protects the language content before it becomes part of the app.

## Content Review Status

Use these statuses in the content spreadsheet:

- `Draft` — contributor is still writing.
- `Needs Review` — ready for language review.
- `Reviewed` — checked by an Ilokano reviewer.
- `Needs Revision` — fix spelling, meaning, grammar, or cultural issue.
- `Ready for App` — developer can add it to the project.

## Recommended Lesson Pattern

Each beginner lesson should have 3–6 questions.

A good sequence is:

1. Recognition: Ilokano to English multiple choice.
2. Recognition: English to Ilokano multiple choice.
3. Meaning check: one short phrase.
4. Typed translation.
5. Review question from an older unit.

## Contributor Spreadsheet Columns

Use the CSV template in `content/lesson-content-template.csv`.

Main columns:

- Stage
- Unit
- Lesson
- Question Type
- Ilokano Word or Phrase
- English Meaning
- Wrong Choices
- Explanation
- Audio Needed
- Contributor Name
- Reviewer Name
- Status

## Accuracy Notes

- Keep beginner sentences short.
- Avoid adding advanced grammar too early.
- Add English explanations that are simple and clear.
- Include alternate English answers when translation is flexible.
- Mark audio-needed items early so pronunciation can be recorded later.
- For gender, avoid forcing Ilokano into English-style gender categories.
